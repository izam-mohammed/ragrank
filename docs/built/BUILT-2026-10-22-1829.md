## In short

ragrank is a Python library, published to PyPI as `ragrank`, that scores a
RAG pipeline: a person hands it questions, retrieved context and responses
(or a callable that runs their pipeline) and gets metric scores back, from
Python, from pytest or from the `ragrank` command line. LLM-judged metrics
call a model through OpenAI, LiteLLM, LangChain or LlamaIndex; the free
metrics need no model. It is installed with `pip install ragrank` and
developed with `uv` (`pyproject.toml`, `uv.lock`). Documentation lives on
Read the Docs, built from `docs/docs/` and `docs/api_reference/` (Sphinx).

## What a person can use

### Evaluating

- `evaluate(data, llm=None, metrics=None, ...)` scores a dataset and returns
  an `EvalResult` with `to_dataframe()`, `to_dict()`, `to_json()`,
  `to_html()`, `usage` and `cost()` (`src/ragrank/evaluation/`; commits
  `e1a7133`, `d90dc7a`, PRs `#65`, `#67`).
- `RunConfig` holds workers, retries with backoff, an on-disk cache,
  repetitions and `raise_on_error` (`src/ragrank/evaluation/`; PR `#67`).
- `target=` runs the user's own pipeline per question
  (`src/ragrank/target/base.py`; PR `#70`).
- `compare()` reports per-metric change with a noise verdict, and `align()`
  measures a judge against human labels (`src/ragrank/evaluation/`; PRs
  `#67`, `#70`).

### Metrics

- Judged: faithfulness, correctness, response relevancy and conciseness,
  context relevancy, utilisation and reliance, safety
  (`src/ragrank/metric/_claims/`, `_response_related/`,
  `_context_related/`, `_safety/`; PRs `#66`, `#67`, `#70`).
- Free: hit rate, MRR, precision and recall at k, NDCG, MAP, exact match,
  token F1, ROUGE-L, Levenshtein ratio, string presence, JSON validity, PII
  and answered checks (`src/ragrank/metric/_retrieval/ranking.py`,
  `_heuristic/`, `_safety/pii.py`; PRs `#66`, `#70`).
- Custom metrics: `@metric`, `LLMJudge`, `Guidelines`, `Jury`, `Pairwise`
  (`src/ragrank/metric/_custom/`; PRs `#66`, `#67`).

### Data in and out

- `from_dict`, `from_csv`, `from_dataframe`, `from_hfdataset`,
  `from_records`, `from_json`, `from_jsonl`, and the matching `to_*`
  writers (`src/ragrank/dataset/`; PRs `#66`, `#67`).

### Models

- `OpenaiLLM` (the default, needs `OPENAI_API_KEY`), `LiteLLM`,
  `LangchainLLMWrapper`, `LlamaIndexLLMWrapper`, and `FakeLLM` for runs with
  no key (`src/ragrank/integrations/`, `src/ragrank/llm/`).

### Command line and pytest

- `ragrank eval <config>` and `ragrank compare <a> <b>`, exit 0, 1 or 2
  (`src/ragrank/cli.py`, `[project.scripts]` in `pyproject.toml`).
- `assert_metric` and a pytest plugin with the `ragrank` marker and
  `--ragrank-report` (`src/ragrank/testing/`, `src/ragrank_pytest.py`).

## Under the hood

- **Shape**: one package under `src/ragrank/`, plus the top-level pytest
  plugin `src/ragrank_pytest.py`; Pydantic imports go through
  `src/ragrank/bridge/pydantic.py` (`CLAUDE.md`).
- **Data**: none stored, except the opt-in on-disk prompt cache
  (`RunConfig(cache=True)`).
- **Integrations**: OpenAI, LiteLLM, LangChain, LlamaIndex, Hugging Face
  `datasets`, all optional extras in `pyproject.toml`; no
  `docs/external/` docs.
- **Standards and CI**: recorded in `docs/standards.md` (written with this
  snapshot). `make lint` (ruff 0.2.2 on `src/` only) runs in
  `.github/workflows/lint.yml` and `make test-offline` in
  `.github/workflows/tests.yml`, both on `push` only, Python 3.11 only.
  `.github/workflows/pypi-release.yml` publishes to PyPI when a GitHub
  release is created; `.github/workflows/build-docs.yml` calls the Read the
  Docs webhooks on the same event. No coverage floor, dependency audit,
  secret scan or reuse of the shared `izam-mohammed/.github` security gate.
- **Releases**: tags `v0.0.1` to `v0.0.10` (no `v0.0.8`), each with a GitHub
  release; the newest, `v0.0.10`, on 29/08/2026 at `b77454a`.
